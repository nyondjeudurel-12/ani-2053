Cette méthode vérifie que `mBackend` existe, puis appelle `mBackend->Clear(c)`. Elle transmet donc la couleur au backend lorsqu'il est disponible. Nous avons observé cette méthode, mais nous n'avons pas confirmé que `NkRenderWindow::Clear` l'appelle directement.

4. Fichier : `Canvas/include/NKCanvas/Renderer/Core/NkIRenderer2D.h` — Fonction : `NkIRenderer2D::Clear(const NkColor2D &color)`. Cette méthode est également virtuelle pure (`= 0`). Elle définit l'opération attendue des backends de rendu.

Arrêt :

`Canvas/include/NKCanvas/Renderer/Core/NkIRenderer2D.h`, sur la déclaration virtuelle pure `NkIRenderer2D::Clear()`.

Pourquoi là :

Le corps de `NkRenderWindow::Clear()` n'a pas été trouvé dans les fichiers du kit examinés. Le kit contient la bibliothèque compilée `Canvas/lib/Debug-Windows/NKCanvas.lib`, mais nous n'avons pas vérifié qu'elle contient précisément cette implémentation. De plus, `NkIRenderer2D::Clear()` est une déclaration virtuelle pure : son corps n'est pas fourni par cette interface. Le suivi s'arrête donc à cette limite du code consultable, sans prétendre avoir observé les instructions exécutées par le backend.

Ce que je sais maintenant :

* Fait observé : `NkCanvasApp::OnRender(NkRenderWindow &target)` ne fait rien dans son implémentation par défaut ; le paramètre est marqué comme inutilisé avec `(void)target`.
